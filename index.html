The spaza owner's daily session

An interactive walkthrough of a replenishment decision-support design for spaza shops: count six products at closing, send the counts from any phone, get a ranked buy list.

Illustrative prototype: advice values are examples, not system output. Not tested with shop owners.

What you are seeing

    
    
      
  • Owner's four actions: count, dial, type the six numbers, buy from the top of the list. The owner works only with digits, numbered keys and the picture columns on the card.
    • 
      
  • Behind the screen (not run here): each evening the engine checks the counts, learns each product's demand from the shop's own counts, and advises an order when stock falls below a reorder level set from that product's demand, lead time and a safety margin. The owner never applies a formula.
    • 
      
  • No phone, signal or power? Counts wait on the card and are sent later. The back of the card holds the last "order when below" levels, so the daily shelf check still works.
    • 
      
  • Channel: USSD works on any mobile phone without a data bundle. Every screen is under 160 characters.
    • 
      
  • What is real and what is not: the screens follow the design specification. The buy list, the reasons and the SMS are fixed examples whatever counts you type. The only check run here is a stand-in for the stock-balance check: a count higher than yesterday's is queried once.
    • 
      
  • Added for this walkthrough: the one-item retype prompt, the read-back without a query, and "1 Back" on the reasons screen, which the specification does not draw.
